# Architecture

## Product boundary

The application turns educational content into a reviewable and renderable video.
It is not a general-purpose video editor. The backend owns the workflow and durable
state; the React application owns user interaction; Remotion owns visual composition
and rendering.

## Runtime components

### Laravel application

`EducationalVideoController` is the HTTP boundary for the workflow:

- `create` exposes available voices, templates, formats, and style previews.
- `store` validates uploads and creates an `EducationalVideo`.
- `show` projects persisted state into the shape consumed by the Inertia page.
- `confirmStoryboard` stores reviewed slide content and resumes generation.
- `retry` resumes a failed pipeline from the last completed stage.
- worksheet endpoints generate and expose the printable companion material.

The controller delegates work to actions rather than embedding pipeline behavior in
route handlers. `EducationalVideo` stores the workflow state, JSON manifests, media
paths, and user-selected options. Backed enums keep the vocabulary shared between
validation, persistence, and rendering.

### Asynchronous pipeline

The pipeline is intentionally split into two chains:

1. `QueueVideoGenerationAction` dispatches `GenerateStoryboardJob`.
2. The job writes a storyboard and changes the video to `awaiting_review`.
3. The user edits or confirms the storyboard in the browser.
4. `ContinueVideoGenerationAction` dispatches the remaining chain:
   `NarrateSlidesJob`, `IllustrateSlidesJob`, `BuildRenderManifestJob`,
   `RenderEducationalVideoJob`, and, for interactive videos,
   `GenerateRemediationVideoJob`.

Each stage updates `status` and `progress` so the UI can show meaningful progress.
The chain failure concern records the failed state and error. Resilient jobs can
retry transient work without losing the domain record.

The review checkpoint is a deliberate product and architecture boundary. It prevents
expensive narration, illustration, and rendering from running on content the user has
not approved, and it makes the AI output inspectable instead of opaque.

### Media and rendering boundary

Laravel stores uploaded source files and provider results using the configured disks.
Before rendering, `BuildRenderManifestAction` copies the selected audio, images, and
logo into `remotion/public/generated/{videoId}` and writes `manifest.json`.

The Remotion project reads only the manifest and its referenced assets. This keeps
the composition deterministic and makes the Laravel-to-Remotion contract explicit:

```text
Laravel media files
        |
        v
manifest.json + generated assets
        |
        v
Remotion EducationalVideo composition
        |
        v
MP4 + still thumbnail
```

`RenderVideoAction` invokes the Remotion CLI as a child process, stores the resulting
MP4 on the public disk, and attempts to create a gallery thumbnail. Thumbnail failure
is non-fatal because it does not affect the playable video.

Interactive remediation clips use a separate `{videoId}-remediation` asset namespace.
That isolation prevents the short follow-up clip from overwriting the main video's
manifest, assets, or render output.

## Frontend boundaries

The Inertia pages under `resources/js/pages/educational-videos` are organized around
the user journey:

- `index.tsx`: generated-video gallery and status overview.
- `create.tsx`: input, source upload, and style selection.
- `show.tsx`: progress, storyboard review, playback, and worksheet actions.
- `components/`: reusable review, preview, player, and selection controls.

The frontend receives serialized view data from the controller. It does not query the
database or call AI providers directly. Route/controller functions are generated by
Wayfinder and imported from `resources/js/actions` and `resources/js/routes`.

## Remotion boundaries

`remotion/src/Root.tsx` registers the public compositions:

- `EducationalVideo`: dynamic composition driven by the generated manifest.
- `FotossintesePortugues`: a static example composition.

`MainSequence.tsx` maps manifest slides to `Series.Sequence` entries. Layouts under
`components/slide-layouts` handle slide-specific visual treatments, while
`components/slide-parts` provides reusable typography, badges, bullets, textures, and
image elements. Themes and animation helpers keep visual decisions out of the
pipeline actions.

`calculateMetadata.ts` derives the dynamic duration from narration timing. This is
important because the composition should match the actual generated audio rather than
use a fixed duration.

## Data and state

The `educational_videos` record is the source of truth for workflow state. Important
groups of fields are:

| Group | Examples | Purpose |
| --- | --- | --- |
| Input | `topic`, `source_pdf_path`, `user_photos`, `logo_path` | User material |
| Choices | `voice`, `template`, `format`, `illustration_style`, `animation_style` | Rendering configuration |
| Workflow | `status`, `progress`, `error` | Pipeline observability |
| AI output | `storyboard`, `interactive_checkpoint`, `worksheet` | Structured generated content |
| Render output | `audio_manifest`, `slide_timings`, `video_path`, `thumbnail_path` | Playback and delivery |

JSON fields are cast by the model so actions and jobs work with typed arrays while
the database remains flexible enough for the different slide types.

## Failure and retry behavior

- Validation failures stay at the HTTP boundary and are returned to the form.
- Chain failures mark the video as failed and preserve the error for inspection.
- Retry resumes work through the pipeline's existing action boundaries.
- Thumbnail failures are logged as warnings and do not fail an otherwise complete
  render.
- A remediation render is appended after the main video and is deliberately isolated
  from the main render's files.

## Extension guide

To add a new slide type:

1. Add the backed enum value and request/storyboard schema fields.
2. Add the corresponding TypeScript type and layout.
3. Register the layout in the slide dispatcher.
4. Include the fields in manifest generation and controller serialization.
5. Add feature coverage for validation, persistence, and rendering data.

To add a new pipeline stage, create an action for provider/file-system work, a
queueable job for orchestration and progress updates, and append it in the appropriate
chain. Keep provider credentials and process invocation behind configuration and
preserve failure visibility in the `EducationalVideo` record.
